# V41：手柄录制与APP编辑互通

64步扩展已按用户要求暂停。本轮只核对两种宏编辑方式能否互通，以及“手柄只能录6步”的现象。

## 互通的静态证据

手柄录制初始化在`0x01e0ba7a`读取活动宏区指针（全局对象`+0x1b8`），用槽号乘`0xdc`定位并清空同一个220字节宏槽。宏上传路径`0x01e093ac`也使用该活动宏区指针和相同槽间距。

命令分发在`0x01e09174`用命令减`0xd4`，经`0x01e09182`开始的6项半字跳转表分发。读取原始表项并计算目标得到：

| 命令 | 表项 | 分支目标 | 本轮确认的行为 |
|---|---:|---:|---|
| D4 | 0x0006 | 0x01e0918e | 配置选择相关，本轮不修改 |
| D5 | 0x00cd | 0x01e0931c | 宏列表/摘要相关，本轮不修改 |
| D6 | 0x00dd | 0x01e0933c | 读取手柄参数配置 |
| D7 | 0x00e8 | 0x01e09352 | 写入手柄参数配置 |
| D8 | 0x0115 | 0x01e093ac | 写入宏 |
| D9 | 0x0172 | 0x01e09466 | 读取指定宏槽 |

D9分支读取请求的槽号，检查槽号小于4，从槽头解析宏长度，用相同的`0xdc`间距定位内容，以D9命令交给发送函数。因此固件内存在读取已录制宏的实现基础。它是否能通过用户设备当前的蓝牙/USB连接完整往返，还没有实机确认。

可考虑实现的统一流程：

```text
手柄录制 → 读取板载宏 → 转换成可编辑时间线
       → 修改、追加或删除动作 → 编码回宏 → 写入并验证
```

不能因此推断官方APP已支持该流程。官方ARMOR X Pro教程明确说明APP无法读取手柄录制的宏：
https://www.bigbigwon.com/support/controller/armor-x-pro-tutorial/

需要在APP或新配套工具中加入读回、解码和编辑后编码功能。内部6字节记录保存的是时间/类型/状态，不是APP的宏JSON行；应保留按下、释放、重叠按键和摇杆状态的时间顺序，不能直接把每条内部记录当成一个普通APP步骤。

本轮没有完成官方Flutter APP的功能修改，也没有生成或安装修改APK。

## “6步”现象

目前不能确认设备存在统一的6步宏上限。

- 该V41镜像已定位的录制容量判断为`0x01e0d59e`的`记录数 < 0x23`，即35条内部记录。
- 宏执行处同样按35条内部记录限幅。
- 记录数组寻址中出现的常数6是每条记录的6字节大小，不能误认为6步限制。
- 官方教程写的是最多15个按键值、30帧；教程没有绑定本轮V41镜像的全部内部计数细节，不能用它替代实机复现。
- 一次用户动作可能导致多次按键/摇杆状态变化；实际只得到6个动作，既不能证明存在固定6步常数，也不能据此认定用户操作有误。

下一项必要证据是设备当前固件版本，以及最小复现：只按A、完全松开，重复至少8次，过程中不碰摇杆，记录设备是否自动退出录制，以及保存后到底回放几次。如果该简单序列也稳定停在6次，再针对该版本和停止原因分析。未确认前不生成“把6改大”的固件。

本轮证据保存在`evidence/macro-command-dispatch.asm`、`macro-readback.asm`、`recorder-init.asm`，上一轮的`record-limit.asm`保留录制计数判断。

## 用户实测更新：第18次按键停止，摇杆转几圈停止

用户随后实测：单按按键18次停止录制，摇杆转几圈就结束。该结果与35条内部记录上限高度吻合：若初始状态未另占记录，17次按下/松开为34条，第18次按下产生第35条，下一轮容量检查结束录制。这里是对实测与静态代码的解释，尚无设备原始宏读回数据以逐条核对。

摇杆录制路径调用`0x01e095fa`，对摇杆四根轴使用约±12000的阈值编码方向状态；`0x01e0ceec`–`0x01e0cef6`比较该编码与上一状态，变化后才设置录制更新标记。它不是把“完整转一圈”作为一个动作存储，也不是每个USB采样帧都无条件写入。不同方向、斜向以及回中会产生新的状态记录，和按键共用35条容量。

因此，本机实测已不支持“手柄固定只能录6个单按动作”的说法。当前问题应改述为：按键和摇杆状态变化共享35条记录，摇杆转圈会较快耗尽容量。

原程序已有状态去重。进一步过滤抖动可以研究滞回或稳定时间，但能节省多少容量尚未验证；不能承诺用普通去重获得任意倍数的录制长度，也不能为了减少记录而默默丢失用户需要的摇杆方向。

互通APP的读回/编辑能让用户整理记录，但不会增加板载容量；若要原样保留更多按键和摇杆变化，仍需容量扩展。64步扩展继续暂停。
